# Тестування

## Загальна вимога

Компонент не може бути доданий до репозиторію лише на підставі успішної синтаксичної перевірки. Для production-готовності потрібні автоматичні перевірки та підтверджена ручна перевірка на реальному обладнанні.

## Автоматичні перевірки

Перед pull request необхідно виконати:

```bash
make test
find . -type f -name '*.sh' -print0 | xargs -0 shellcheck --severity=warning
find . -type f -name '*.sh' -print0 | xargs -0 shfmt -d -i 4 -ci
```

Додатково перевіряються:

- валідність JSON через `jq -e`;
- імпорт YAML-шаблонів у Zabbix 7.4;
- наявність усіх production-файлів компонента;
- атомарне оновлення кешу;
- збереження попереднього справного кешу при помилці збору;
- повторний запуск інсталятора.

## Ручна перевірка SMART

SMART перевіряється щонайменше на доступному реальному накопичувачі SATA, SAS або NVMe. Необхідно підтвердити:

- виявлення пристрою через `smartctl --scan-open`;
- формування валідного JSON;
- коректні значення стану SMART, температури та лічильників;
- роботу systemd service і timer;
- читання кешу через Zabbix Agent 2;
- коректну роботу LLD, dependent items і тригерів.

## Ручна перевірка Sensors

Sensors перевіряється на реальному сервері або вузлі Proxmox VE, де команда `sensors -j` повертає апаратні показники. Необхідно підтвердити:

- формування валідного JSON;
- правильну класифікацію температур, вентиляторів, напруг, струму та потужності;
- відсутність помилок, якщо частина типів показників недоступна;
- роботу systemd service і timer;
- читання кешу через Zabbix Agent 2;
- коректну роботу LLD, dependent items і тригерів.

## Протокол перевірки

Перед release у `CHANGELOG.md` або супровідному pull request необхідно вказати:

- платформу та її версію;
- версію Zabbix Agent 2;
- тип перевіреного обладнання без публікації чутливих серійних номерів;
- перелік виконаних перевірок;
- відомі апаратні обмеження.
